# Сопоставление деклараций и регулирующих НПА

## Задача

Для каждой таможенной декларации необходимо определить 10 наиболее релевантных нормативно-правовых актов (НПА) и вернуть их в порядке убывания релевантности.

В исходных данных отсутствует эталонная разметка, поэтому для выбора метода дополнительно использовалась небольшая диагностическая выборка со слабыми метками.

## Структура проекта

В корне проекта находятся:

* `run.py` — запуск итогового решения;
* `project_setup.py` — установка зависимостей и загрузка моделей;
* `requirements.txt` — зафиксированные версии библиотек;
* `experiments.ipynb` — разведочный анализ данных и эксперименты;
* `data/` — исходные данные и созданная разметка со слабыми метками;
* `models/` — локальные файлы моделей;
* `src/` — исходный код отдельных компонентов решения;
* `out/` — результаты работы программы.

## Установка и запуск

Установить зависимости и загрузить модели:

```bash
python project_setup.py
```

Подготовка выполняется один раз до основного запуска.

Запуск выполняется из корня проекта:

```bash
python run.py --out ./out
```

Для использования другого расположения данных или моделей:

```bash
python run.py \
    --data-dir ./data \
    --models-dir ./models \
    --out ./out
```

Программа автоматически использует `CUDA`, если доступна видеокарта, иначе работает на `CPU`.

## Воспроизводимость

Основной запуск не выполняет сетевых запросов. Модели и зависимости подготавливаются заранее и затем используются из локальных файлов.

## Подход

Перед поиском текст приводится к единому виду: нормализуется Unicode, переводится в нижний регистр и нормализуются пробельные символы. Пунктуация, числа и технические обозначения сохраняются.

Итоговое решение использует семантический поиск на основе `BAAI/bge-m3`.

### 1. Лексический поиск BM25

В качестве базового метода был реализован BM25.

Он использует буквальные совпадения слов и хорошо учитывает термины, числа и технические характеристики. Однако при различном описании одного и того же понятия совпадения могут отсутствовать, поэтому одного лексического поиска недостаточно.

### 2. Семантический поиск

Для получения векторных представлений текстов используется `BAAI/bge-m3`.

Векторные представления НПА вычисляются один раз перед обработкой деклараций. Для каждой декларации вычисляется её вектор, после чего он сравнивается со всеми НПА по косинусному сходству.

Корпус содержит всего 562 НПА, поэтому полный поиск по корпусу является достаточно дешёвым и не требует отдельного индекса для быстрого поиска ближайших соседей.

### 3. Сравнение методов

В ходе экспериментов были рассмотрены:

* BM25;
* BGE-M3;
* объединение BM25 и BGE-M3 с помощью Reciprocal Rank Fusion (RRF);
* BGE-M3 с последующим переранжированием с помощью `BAAI/bge-reranker-v2-m3`;
* RRF с последующим переранжированием.

Для сравнения использовалась диагностическая выборка из 20 деклараций. Для кандидатов была получена бинарная слабая разметка с помощью языковой модели:

* `1` — между товаром и НПА видна содержательная связь по предоставленным текстам;
* `0` — содержательная связь по предоставленным текстам не видна.

Разметка использовалась только для сравнительного эксперимента и не является эталонной.

На этой диагностической выборке BGE-M3 показал более высокие значения Precision@10 и NDCG@10, чем BM25. Добавление RRF и последующее переранжирование не улучшили результат относительно непосредственного использования BGE-M3.

Поэтому в итоговом решении используется BGE-M3 без дополнительных этапов объединения результатов и переранжирования.

## Сложности задачи и их учёт

### Отсутствие эталонной разметки

В исходных данных нет правильных соответствий между декларациями и НПА. Поэтому невозможно напрямую оценить качество ранжирования на всей выборке.

Для выбора метода была создана небольшая диагностическая выборка со слабыми метками. Она позволяет сравнивать разные методы на одних и тех же данных, но не рассматривается как полноценная эталонная оценка.

### Сложные текстовые соответствия

Даже семантические представления не всегда корректно различают близкие, но неэквивалентные товары и характеристики. В текстах могут встречаться товары одного класса, разные варианты одного типа продукции или НПА с похожим описанием, но относящиеся к другой характеристике товара.

Поэтому в экспериментах дополнительно проверялись объединение лексического и семантического поиска и переранжирование кандидатов. Однако на диагностической выборке эти дополнительные этапы не улучшили результат BGE-M3 и поэтому не вошли в итоговое решение.

### Числовые и технические характеристики

Для некоторых товаров релевантность может зависеть от конкретных числовых значений, моделей, размеров, единиц измерения или других технических характеристик. Такие различия могут недостаточно хорошо учитываться семантическим сходством текста.

### Ограничения слабой разметки

Слабые метки зависят от выбранного критерия релевантности и качества использованной языковой модели. Поэтому значения Precision@10 и NDCG@10 из этого эксперимента не следует трактовать как абсолютное качество итоговой системы.

## Итоговое решение

Для каждой декларации:

1. текст товара нормализуется;
2. BGE-M3 получает векторное представление декларации;
3. вычисляется косинусное сходство со всеми 562 НПА;
4. выбираются 10 НПА с наибольшими значениями сходства;
5. результаты сохраняются с рангами от 1 до 10.

В качестве `score` используется косинусное сходство между вектором декларации и вектором НПА. Чем больше значение, тем выше позиция НПА в результате поиска.
